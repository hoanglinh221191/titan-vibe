# TITAN-VIBE: the VIBE-only build of TITAN

`make VIBE_ONLY=1 all` builds `titan-vibe` (`titan-vibe.exe` on Windows):
VIBE (`-pbctopo`) with the readers and writers it needs, and none of TITAN's
energy, solvation, kinetics or analysis modules.

What it contains:

- the structure, index, GROMACS topology and trajectory (xtc, trr) readers,
  and the force-field library that types atoms when no topology file is given;
- VIBE (`src/pbctopo/`, `src/solv_pbc_pbctopo.cpp`) and the older periodic
  image code it calls (`src/solv_pbc_new_al.cpp` and its helpers);
- the TITAN engine (`src/engine/`, without the energy frame body `frame.cpp`)
  and the PDB writer.

The source list is `VIBE_ROOT_SRCS` and the `VIBE_ONLY` block of the Makefile.

## How the modules are left out

The engine decides at run time which modules a run uses, so it names the entry
points of every module. This directory supplies them for the modules that are
not compiled:

| File | Role |
|---|---|
| `option_allowlist.cpp` | The options TITAN-VIBE accepts. `parse_arguments()` refuses any other option before it is parsed, so no run can enable a missing module. |
| `absent_entry_points.cpp` | Generated by `tools/vibe_only/generate_absent_entry_points.py`. One definition per entry point. Those listed in `disabled_entry_points.txt` do nothing and return a value-initialized result (the module with its options off); every other one calls `titan_vibe_only::absent()`, which stops the program with an internal error. |
| `disabled_entry_points.txt` | The entry points the engine calls on every run (configuring each analysis object, the end-of-run post-processing stages, ...), with the reason. |
| `disabled_modules.cpp` | Hand-written. The constructors and destructors of the analysis objects the engine holds, and the few entry points whose definition needs a type the headers leave incomplete. |
| `absent.h`, `absent.cpp` | `titan_vibe_only::absent()`. |

TITAN-VIBE also requires `-nocal=true` (every run writes coordinates) and
prints the VIBE reference for `-h`.

## When the engine changes

If the link of the VIBE-only build reports undefined symbols, regenerate the
table from the link log:

```bash
make VIBE_ONLY=1 PROFILE=portable all LDFLAGS="<the usual flags> -Wl,--no-demangle" 2> link.log
python tools/vibe_only/generate_absent_entry_points.py --link-log link.log --append \
    --clang clang++ --cxxflags "<the -I and -D flags of the build>"
```

A new entry point that the engine calls on every run shows up as an
"internal error" when the examples run. Check that the real function does
nothing when its options are off, add its name to `disabled_entry_points.txt`
and rerun the script with `--append`. If its definition needs an incomplete
type, write it in `disabled_modules.cpp` and drop it from the table with
`--remove NAME`.

## Checks

The outputs of `titan-vibe` must equal those of the full `titan` build on the
same inputs: the quick-start examples, the 480 held-out cases and the 367
frames of the five molecular systems (`replay.py`, `replay_real.py` in the
TITAN-VIBE package).
